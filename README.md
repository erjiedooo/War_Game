# War_Game

War_Game 是一款以中国北方八省区市真实地级行政区划为战场的回合制领地战略游戏。项目同时保留完整单机模式，并提供基于 Node.js、Express 和 Socket.IO 的 2–4 人局域网联机模式。

## 当前功能

- 84 个真实地级行政区，覆盖北京、天津、河北、山西、内蒙古、辽宁、山东、河南。
- 行政区边界来源于国家地理信息公共服务平台“天地图”2024 行政区划数据，经 `reverse-geocoder-cn` 边界包提取；审图号 GS(2024)0650号。
- 黄河、海河、滦河、辽河、淮河五大水系，以及太行山、燕山、辽西丘陵、泰山和内蒙古沙漠地形。
- 单机“十雄逐鹿”“八方割据”模式，NPC 基于回合初始快照同步部署。
- 局域网 2–4 人房间：创建/加入、房主、人数上限、势力选择、准备、开局和房间锁定。
- 联机“开拓模式”与“割据模式”：前者保留十雄与中立地区，后者复用单机八方割据的固定 84 城版图；未被真人选择的势力由服务器 NPC 接管。
- 可选“天险与军事重镇”规则：抽象线形山脉阻断陆路，山口与河防重镇获得 25% 防御加成。
- 权威服务器：客户端只提交意图，兵力、所有权、合法路径、同步战果、增长和胜利均由服务器判定。
- 真人玩家无部署先后顺序；全部真人提交后，NPC 依据回合初始快照生成命令，再由服务器统一结算。
- 顶栏实时显示与权威服务器的往返延迟。
- 联机自动存档、手动保存、掉线暂停、同席位重连和服务器重启恢复。
- 自由划线部署、最多跨一座己方城市、每城最多两路、最低留守 1 兵。
- 遭遇战、多方混战、分割包围、首都迁移、机场、港口、独立舰队与陆海空协同。
- 单机回档、动态行军/战斗动画、战报、缩放和平移。

## 快速运行

推荐直接双击 `启动游戏.cmd`。脚本会检查 Node.js 和 npm；首次运行如果缺少依赖，会执行 `npm install`，随后启动服务器并打开浏览器。

也可以手动运行：

```powershell
npm install
npm start
```

然后访问 <http://127.0.0.1:4173/>。Node.js 需要 18 或更高版本，当前开发验证环境为 Node.js 24。

## 局域网联机

1. 房主在一台电脑运行 `npm start` 或双击 `启动游戏.cmd`。
2. 服务器窗口会打印本机地址和一个或多个 `LAN` 地址，例如 `http://192.168.1.10:4173/`。
3. 房主打开页面，选择“局域网联机”，输入名称，选择十雄开拓/八方割据地图与是否启用天险，再创建 2、3 或 4 人房间。这些设置开局后不能更改。
4. 其他玩家在同一局域网内访问服务器打印的 `LAN` 地址，输入名称和 6 位房间码。
5. 每名玩家选择一个未占用的历史势力并点击“准备”；未被选择的势力会在开局时自动交给 NPC。
6. 至少 2 人且所有人准备后，房主点击“开始游戏”。开始后房间锁定。

如果其他电脑无法访问：

- 确认所有设备处于同一局域网，且使用服务器输出的 LAN 地址，不是 `127.0.0.1`。
- Windows 防火墙可能首次询问是否允许 Node.js 访问专用网络；需要由用户在系统提示中允许。
- 确认 TCP 4173 端口没有被防火墙或其他程序阻止。
- 项目不会自动修改防火墙设置。

## 联机回合模型

联机游戏使用动态 `players[]`，支持 2–4 人，不使用固定 player1/player2 或红蓝阵营。

每轮所有存活真人同时进入部署阶段，彼此均可创建、修改和取消自己的命令，不存在行动顺序。玩家只能看到自己的命令；提交后不能再次修改。全部真人提交后，服务器 NPC 才开始部署，但 NPC 只读取本回合开始时的领地与兵力快照，无法看到或针对玩家刚提交的路线。随后服务器一次性同步结算真人与 NPC 的全部命令，统一增长并开始下一轮。被消灭玩家会自动跳过。

断线与存档：

- 每次房间或战局变更都会原子写入 `saves/rooms.json`；游戏内“保存战局”可立即手动落盘。
- 浏览器只保存房间码、玩家 ID 和随机重连令牌；领地、兵力与命令仍只以服务器存档为准。
- 大厅或游戏中断线都会保留席位。游戏中有玩家断线时整局自动暂停，未提交部署不会丢失。
- 原玩家使用同一浏览器再次进入“局域网联机”会自动认领席位；全部存活玩家重连后自动继续。
- 服务器重启会加载存档并保持暂停，等待全部玩家重新连接。房主也可手动暂停/继续。
- 当前版本不支持观战、中途补位或账号系统；清除浏览器站点数据会丢失该浏览器的重连凭证。

## 权威状态与消息

服务器持有完整 `GameState`：房间码、阶段、轮次、真人与 NPC 动态数组、84 个领地、回合初始快照、舰队、隐藏部署、已提交玩家、胜者、最近结算和战报。

客户端使用的主要事件：

- 上行：`createRoom`、`joinRoom`、`resumeSession`、`leaveRoom`、`setPlayerName`、`selectFaction`、`setReady`、`startGame`、`stageOrder`、`cancelOrder`、`startConstruction`、`cancelConstruction`、`endTurn`、`saveGame`、`setGamePaused`、`requestState`。
- 下行：`roomState`、`gameState`、`gameStarted`、`gameEnded`、`playerJoined`、`playerLeft`、`errorMessage`。

所有改变状态的请求都根据 Socket 身份查找真实 `playerId`；客户端不能在请求中伪造玩家身份或控制 NPC。服务端会验证房间、游戏阶段、是否已经提交、领地所有权、兵力预算、路线、机场数量与范围、港口及目标合法性。

## 规则摘要

- 普通城市兵力上限 30；拥有机场且达到 30 兵时升级为特大城市，上限 45。
- 补给畅通、未建设的非中立城市每回合增长 3 兵；领地越多，总增长越多。
- 每个据点每回合最多出发两路部队，两路合计必须至少留下 1 名守军。
- 陆路最多经过一座己方中间城市；地图划线路径用于箭头和地形判定，城市拓扑用于合法性判定。
- 己方调动无地形损耗。普通地形规则下，进攻跨河损耗 15%，穿越山脉/丘陵损耗 20%，穿越沙漠损耗 15%。
- 联机建房时可启用“天险与军事重镇”：太行、燕山、辽西丘陵及中条—崤山以抽象线形障碍阻断指定陆路边，陆军须改走山口重镇；空降与海运可绕过山脉。
- 军事重镇包括张家口、大同、阳泉、长治、锦州、三门峡、唐山、沈阳、济南和郑州；天险规则开启时守军防御 +25%。
- 相向进攻先在途中进行遭遇战，胜者扣除战损后继续任务，败者出发城市仍会失去已派兵力。
- 机场和港口建设均需 8 个增长阶段，建设期间城市不增长；每个势力最多拥有 4 个机场，已建、在建和本轮待提交机场均计入上限。
- 机场允许向 700 公里内城市空降，损耗 25%。
- 港口允许登陆敌方沿海城市，损耗 30%；登陆兵力成为独立海上舰队。
- 两军种协同进攻加成 20%，陆海空齐备加成 45%；战后城市驻军只保留陆军和空降兵。
- 首都防御 +15%，失守后自动迁都；特大城市防御 +25%；普通地形规则下山地守军防御 +25%。
- 与首都的陆路、机场或港口补给线被切断时进入包围：防御 -25%、停止增长、每回合损失 1 兵。
- 最后一名仍拥有领地的玩家获胜。

## 架构说明

地图 GeoJSON 继续由浏览器通过静态 HTTP 直接加载，服务器不通过 Socket.IO 广播大体积地图数据。客户端负责输入、预览、绘图、动画和界面；服务端持有唯一可信状态并广播事件驱动的完整快照。

单机模式与联机模式使用独立编排入口，避免联机迁移破坏现有 NPC、同步回合、回档和地图体验。纯配置与几何算法拆成 ES Modules 复用；联机结果规则只在服务器执行。

## 当前限制

- 当前只有单一存档槽文件，不提供存档列表、命名存档或历史版本回档。
- 不支持账号、数据库、观战和中途补位；重连身份依赖该浏览器保存的随机令牌。
- 联机模式不提供历史回档，避免客户端单方面撤销权威服务器状态。
- 单机模式继续提供回档；联机模式不提供历史回档，NPC 和真人的结算都由权威服务器保存。
- 联机开拓模式固定为十个势力，割据模式固定为八个势力；房间仍允许 2–4 名真人，其余席位全部由 NPC 补齐。
- 路径折线是玩家提交的行动意图，服务端会限制坐标数量、战区范围和端点，并独立计算地形损耗；本 MVP 不包含反作弊级路径寻路证明。
