# War_Game 重构基线

记录时间：2026-10-05

## 工作区保护

- 当前目录不是 Git 仓库，因此没有可供检查的分支、提交或未提交修改状态。
- 本轮不自动初始化 Git，也不覆盖或删除现有 GeoJSON 与地图生成工具。
- 重构按可运行阶段推进；每个阶段先做语法与启动验证，再进入下一阶段。

## 当前文件与职责

- `dist/index.html`：完整游戏页面、SVG 地图容器、命令侧栏、势力选择、规则、回放、战报与胜负弹窗。
- `dist/styles.css`：地图、兵力标记、地形、水系、舰队、命令、动画、面板和响应式样式。
- `dist/app.js`：1722 行单文件前端，混合了配置、状态、地图投影、路线判定、UI、NPC、战斗、增长、动画、回档和 WebMCP 注册。
- `dist/data/northern-theater.geojson`：84 个地级行政区，覆盖北京、天津、河北、山西、内蒙古、辽宁、山东、河南。
- `dist/data/northern-rivers.geojson`：67 个 Natural Earth 水系要素；运行时筛选黄河、海河、滦河、辽河、西辽河、淮河。
- `dist/data/northern-mountains.geojson`：太行山、燕山、辽西丘陵、泰山、库布齐沙漠、乌兰布和—腾格里沙漠 6 个战略地形廊带。
- `dist/data/official-map.geojson`：早期河北周边 13 个行政区边界，当前主地图不直接加载，保留为数据资产。
- `tools/*.mjs`：行政区、水系、山脉数据构建脚本，重构后继续保留。
- `启动游戏.cmd`：当前使用 Python 静态服务器；联网阶段将改为检查 Node.js、安装依赖并启动权威服务器。

## 当前状态模型

单机状态包含：`round`、`mode`、`factionIds`、`phase`、`playerFaction`、`territories`、`playerOrders`、`npcOrders`、`fleets`、选择状态、回档历史、闪烁标记与结束状态。

领地状态包含：所属势力、驻军、机场、港口、特大城市、建设进度和首都归属。地图定义另存城市名称、省份、标注坐标、地形影响与相邻关系。

## 当前回合与战斗流程

1. 玩家选择“十雄逐鹿”或“八方割据”以及一个势力。
2. NPC 基于同一回合初始快照预先锁定命令。
3. 玩家自由划线下达最多两路陆路、空降或登陆命令。
4. 结束部署后播放行军动画。
5. 先扣出征兵力和路线损耗，再处理相向进攻的遭遇战。
6. 登陆兵力生成独立舰队并先处理舰队战。
7. 同一目标按陆海空协同、地形、首都、特大城市、包围状态进行多方战斗。
8. 迁都、建设、包围损耗与每领地增长结算。
9. 生成战报，检查玩家胜败，生成下一回合 NPC 命令。

## 必须迁往服务端的权威逻辑

- 房间、玩家、房主、准备、势力占用与开局条件。
- 游戏状态、当前行动玩家、淘汰跳过、回合与轮次推进。
- 所有命令身份、所有权、兵力、路线、设施、范围和目标合法性验证。
- 出征预算、地形损耗、遭遇战、舰队战、协同加成、多方攻城。
- 首都迁移、补给与包围、建设、增长、淘汰与最后存活者胜利。
- 完整状态广播和错误响应。

## 保留在客户端的表现逻辑

- GeoJSON 直接静态加载、投影、行政区和地形水系绘制。
- 缩放、平移、城市选择、自由划线与路线预览。
- 命令列表、按钮、提示、实力榜、房间大厅和连接状态。
- 服务端结算结果驱动的行军、战斗动画与战报展示。
- 单机模式的 NPC 与回档能力；联机模式不允许客户端回档。

## 分阶段计划

1. 前端 ES Modules：配置、状态、几何/地图、战斗、回合、UI、网络适配层；单机功能继续可运行。
2. Node.js + Express + Socket.IO：先提供静态资源与健康检查，再加入房间系统。
3. 权威多人规则：动态 2–4 人、服务端验证、同步结算、轮转与胜利。
4. 大厅与联机 UI：创建/加入、房主、准备、势力选择、连接状态与错误提示。
5. 启动脚本、README、自动化多人烟雾测试和浏览器回归验证。
